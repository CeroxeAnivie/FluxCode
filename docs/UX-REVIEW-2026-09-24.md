# 交互复查：首次使用与工作连续性

本轮从没有真实渠道、没有项目的使用状态出发。电脑上实际打开的是安装目录中的旧版本；通过 computer-use 观察空白主页、打开模型选择、取消并进入服务设置。新构建进程的直接启动被执行策略拒绝，应用启动接口仍解析到已安装版本。因此，下列新行为已有浏览器端回归验证，但不能据此宣称已完成新版 Windows 窗口的人工式操作验收，更不能宣称真实渠道已接通。

## 观察与修复

| 用户动作 | 原先的阻碍 | 当前实现 |
| --- | --- | --- |
| 没有渠道时选择模型 | 先出现“添加模型”，要求用户知道模型 ID | 直接进入渠道管理 |
| 添加服务 | 连接、模型、外观混在一个长设置表单中 | 独立渠道页，地址和密钥为主，名称可选 |
| 导入模型 | 需要先查询再单独选择 | 主按钮获取并保存全部模型，搜索不裁剪目录 |
| 按 Enter | 与主按钮行为不同 | 与“导入并使用”一致，任务运行时明确改为仅保存 |
| 手动输入多个模型 | 保存前还需再点添加 | 保存时自动合并、去重 |
| 导入失败 | 错误可能藏在折叠区 | 错误常显，保留输入，可直接重试 |
| 临时关闭渠道窗口 | 输入需要重填 | 未保存表单在当前运行期间保留，密钥只留内存 |
| 先写任务，再选择项目 | 项目切换后看不到刚写的内容 | 无项目草稿与附件迁入首次选择的项目 |
| 搜索不到渠道 | 空白列表缺乏反馈 | 显示无匹配结果和清除搜索入口 |
| 离开未保存的设置 | 上下文输入被丢弃 | 提示继续编辑或放弃修改 |
| 取消系统导出框 | 任务操作窗口也关闭 | 保持原窗口，允许继续操作 |
| 本地草稿存储失败时关闭文件面板 | 可能隐藏尚未持久化的编辑 | 导航保护保留编辑器和失败提示 |

## 验证边界

- 回归覆盖首次使用、多个渠道、完整目录、350 模型搜索、失败重试、键盘提交、取消与草稿保存，以及任务、编辑器、终端和主题语言流程。
- 未向真实服务发送请求，未保存真实密钥。
- 新版 Windows 原生交互验收、真实渠道连通性、干净机器安装与数字签名验收仍不能标记完成。
- 本轮没有新增第三方依赖；渠道 TOML 的模型列表兼容旧版仅有默认模型的记录。旧配置保留，未执行破坏性迁移。
