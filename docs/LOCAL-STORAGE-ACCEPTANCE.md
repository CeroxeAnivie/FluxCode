# 项目内运行与数据存储验收

## 已实现

在项目根目录执行 `pnpm desktop:run`，构建后直接启动 Windows 桌面程序，不生成或安装安装包。已有构建使用 `pnpm desktop:run -NoBuild`。热更新开发仍使用 `./scripts/dev.ps1 dev`。

开发版具有独立应用标识，避免被安装版的单实例机制接管；默认数据位于 `src-tauri/target/debug/data`。发行版数据位于 `FluxCode.exe` 同目录的 `data`。Codex 的 SQLite、JSONL 会话文件、WebView 的任务索引/草稿/队列，以及应用 TOML 和日志都纳入该目录。凭据仍使用系统凭据库。

发行版首次启用新路径时复制旧数据，通过临时目录和重命名发布完整结果，不删除原件、不合并覆盖已有 `data`。SQLite 中引擎自有会话文件路径随迁移调整；整个数据目录再次移动时按存储布局记录重定位。开发版不会自动复制安装版数据。

Windows 启动时会根据现有显示器工作区校正已保存的窗口位置和大小；若高 DPI 下最小窗口尺寸大于工作区，至少保持窗口左上角可达。初始化数据目录失败时会显示系统错误对话框并以非零状态退出。诊断对话框仅显示经过限制的启动原因，不回显未知错误详情或密钥。

## 验证

- Rust 自动化测试通过，包括目录解析、完整复制、迁移失败不发布半份数据、禁止覆盖、SQLite 会话路径迁移、大小写变化、中文路径和长路径再次移动；严格 Rust Clippy 检查通过。
- 前端类型检查和生产构建通过。前端单元与浏览器测试的最新总结果以统一验证记录为准。
- 未安装新软件，从项目内可执行文件启动完成原生测试：模型目录导入、真实内置引擎对接本地模拟 Responses、发送、压缩、推理档位、终端、TOML 热重载、分支和单实例。
- 测试完整关闭并重新启动进程，恢复任务索引和对话正文；检查 SQLite 和 WebView Local Storage 位于指定的同一数据目录。
- `pnpm desktop:run -NoBuild` 已实际执行，并确认窗口进程来自项目 `target/debug`。通过 computer-use 读取该窗口，确认显示新版渠道入口。
- 原生验收发现并修复配置重连竞态：等待空闲后重新读取当前配置，避免旧监听快照覆盖刚完成的界面保存。
- 新增存储依赖的许可已收集，OSV 对八个新增包版本未返回通告；不代表全应用无安全风险。
- 自动化测试覆盖目录仅改变大小写后再次移动、中文路径、长路径，以及窗口在副屏消失和工作区缩小时的位置计算。真实多显示器与各 DPI 档位仍需原生窗口验收。

长路径测试证明 FluxCode 的迁移代码可读取并重定位 SQLite 索引；内置 Codex 引擎对长路径项目和会话的端到端兼容性尚未单独验收。

## 与成熟 Windows 本地产品的剩余差距

1. 真实服务兼容矩阵：多个 Responses 渠道在限流、长流式响应、断线、工具调用和压缩上的差异，尚未全面验收。
2. 故障恢复深度：备份与恢复中心已实现，仍需系统性的强制结束进程、磁盘写满、数据库损坏、休眠恢复及长时间运行验收。
3. 交互一致性：全应用键盘焦点、读屏、高 DPI、多显示器与中文输入法仍需完整审查。不能用局部操作通过替代全应用体验验收。
4. 并发工作流：多窗口、多个独立代理并行工作的监督界面仍需验收；Git 逐行暂存与合并/变基冲突流程需要完整原生操作验收。
5. 交付可信度：缺正式数字签名、干净 Windows 环境的安装/升级/卸载矩阵，以及持续性能指标和完整上游引擎依赖安全审查。

不把用户明确暂缓的 Linux/macOS、云同步和在线更新列作本期缺陷。旧安装包不包含本轮存储布局改动，应以当前项目构建为准。真实旧账户迁移的端到端验收仍待完成，现有迁移证据来自隔离自动化测试。
