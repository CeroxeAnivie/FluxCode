# 多窗口协作与运行容量

打开项目后，点击标题栏的“在新窗口打开工作区”。最多同时打开 8 个附加工作区窗口。
各窗口都能选择项目和任务、发送消息、选择模型与推理强度、管理待发送消息、回答工具问题、编辑文件、处理 Git 变更，以及使用终端和右侧浏览器。
渠道及全局设置在主窗口统一管理；附加窗口中的“打开主窗口”可随时返回。

## 状态与所有权

- Rust 宿主拥有唯一的执行引擎，所有窗口共用连接。
- 主界面是任务索引与待发送队列的唯一写入者。附加窗口的共享操作通过带请求编号的宿主通道提交，结果与错误只返回发起窗口。
- 主界面向各窗口推送共享项目/任务索引及该窗口正在查看的会话状态，不广播其他会话的完整正文。
- 每个附加窗口独立保存当前选择、草稿、附件、滚动位置和面板。窗口编号复用，关闭后再次打开可恢复自己的工作现场。
- 每个窗口使用独立的 WebView2 数据目录。窗口镜像位于 `data/windows/workspace-N/`；WebView2 缓存位于 `data/webview/workspace-N/`。
- 文件写入继续使用现有的原内容比较和冲突处理。不同窗口编辑同一文件时，不会跳过过期检测直接覆盖。
- 同目录或嵌套目录内有其他活动任务时显示共享文件提醒。需要隔离修改时使用 Git 工作树。

## 关闭与恢复

- 关闭主窗口而附加窗口仍打开时，主窗口隐藏，继续协调任务和队列。
- 关闭附加窗口前保存其工作现场，并结束该窗口拥有的交互终端和命令模式进程；等待实际退出释放额度后才销毁窗口，不停止其他窗口的终端和对话任务。关闭期间拒绝该窗口新建终端，退出超时保留窗口并显示可重试提示。
- 最后一个可见工作区窗口关闭后进入程序退出流程。若仍有运行任务或终端，会明确确认退出。
- 主界面重新加载或连接状态变化时通知附加窗口刷新；窗口回到前台也会重新读取选中任务状态。
- 请求结果不明时报告错误并保留输入，不自动重发。用户先刷新任务状态，再决定是否重试。
- 恢复备份前须关闭附加窗口，避免恢复数据与窗口写入竞争。各窗口的已持久化镜像纳入现有备份；WebView2 缓存不直接复制。
- `WEBVIEW2_USER_DATA_FOLDER` 会覆盖 WebView2 的独立目录设置，因此设置此变量时明确拒绝创建附加窗口。项目启动脚本清除子进程中的该变量，由宿主分配目录。

## 运行上限

| 资源               | 全局上限 | 达到上限时                               |
| ------------------ | -------: | ---------------------------------------- |
| 用户提交的并行任务 |        8 | 拒绝新启动，保留输入；停止或等待后可重试 |
| 交互终端及命令进程 |       16 | 拒绝新建；结束已有进程后释放容量         |
| 附加工作区窗口     |        8 | 提示已达上限                             |
| 引擎等待请求       |      128 | 其中 8 个名额保留给停止、中断和终端控制  |
| 窗口协调请求       |       32 | 其中 4 个名额保留给停止任务              |

任务启动预留是原子的，同一任务不能同时启动两轮。取消、失败及正常返回都会释放临时请求占用。
任务实际完成前仍保留运行状态。退出程序沿用 Windows Job Object 统一清理执行引擎及其后代进程。
这些是应用提交与协调的容量限制，不是对完全访问工具施加操作系统 CPU/内存沙箱。

设置中的“本机运行环境”显示当前占用和上限。导出的诊断包含任务、请求、终端和窗口计数，不包含提示词、任务正文或密钥。
轻量资源计数接口不执行引擎文件哈希或依赖探测，避免资源状态读取被完整诊断扫描拖慢。

## 项目目录启动

```powershell
pnpm desktop:run
# 已构建后直接启动
pnpm desktop:run -NoBuild
```

本轮专用本地流程为 `node scripts/native-multiwindow-smoke.mjs`：它使用声明的本地 Responses 夹具、隔离数据目录与真实 Windows WebView2，不使用生产渠道或真实密钥。
