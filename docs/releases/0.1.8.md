# FluxCode 0.1.8 — 看得见的错误与可靠的子智能体协作

日期：2026-10-04。Windows x86_64，继续复用已捆绑的 0.157.0 执行引擎，不重新编译上游引擎。

- 修复普通 Responses 渠道未返回加密参数标记时，子智能体明文任务被错误识别为加密内容的问题。模型工具统一使用直接调用；本地认证传输适配器补全明文协作标记，保留真实加密推理内容。HTTP 限流状态和 Retry-After 原样保留。
- 子智能体即使没有输出正文，也能在侧栏和详情中看到失败原因。重新打开父会话或未加载的子会话时恢复失败状态及原始原因。失败回合不再清空先前收到的诊断，失败工具不再显示成功勾号。
- 浏览器操作和智能体回执、图片与文件链接、配置监测、主题读取、语法高亮加载、模型目录获取和 Git 操作保留具体失败原因。界面直接显示脱敏详情；复制诊断是辅助操作。服务没有返回原因时明确说明，不伪造结论。
- 默认按手动配置、进程环境、Windows 系统代理的顺序解析网络路由。读取已启用的手动代理与 PAC；不可用代理报告原因。模型请求、模型列表与远程图片统一使用该策略，图片重定向逐地址解析。新终端和执行引擎继承启动时的代理环境。渠道高级设置提供网络代理检查。
- 内置 WebView2 开启原生 Ctrl + 滚轮缩放；手动缩放期间停止自动适宽补偿，Ctrl + 0 恢复自动适宽。补齐框架网页和页面缓存恢复处理。
- 修复面板展开动画的结束计时早于动画实际开始的竞态。

没有数据库格式迁移。没有写入本机代理地址。没有修改用户会话或重新执行用户任务。

网络检查确认代理 TCP 端口是否可连接，不能代替远端鉴权与模型可用性检查。应用 HTTP 客户端逐请求解析 PAC；任意终端程序得到的是启动时的代理环境，是否遵循代理取决于该程序。企业 PAC/代理认证组合和原生滚轮手感仍需实际环境验收。429 属于服务限流，应用显示原因但不能消除服务配额限制。
