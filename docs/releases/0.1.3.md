# FluxCode 0.1.3 — Windows acceptance

Date: 2026-10-04

## Delivered behavior

The desktop now separates global navigation, project/task navigation, conversation and optional tools. The composer has no fixed maximum width. Channels retain their directory while editing; switching away from a dirty draft requires an explicit discard. Settings keep categories visible beside their scrollable content. BrandMark is an original SVG used at header and welcome sizes. Translucency is implemented in the WebView surfaces, with an opaque fallback; it does not require a native Windows Acrylic window effect.

The Cherry Studio design/layout reference was inspected at commit 79381a8ff9283037215aa3a2d1ea458cdc0010cf. Its source and assets were not copied. FluxCode retains projects as its primary organizational unit. This is not a claim of pixel-identical reproduction.

## State invalidation review

| Scope | Correction / policy |
| --- | --- |
| Channel connection draft | Address, key, credential identifier and proxy changes invalidate catalogue, aliases, exclusions, manual input and row selection/filter. |
| Model discovery | Replace on success; preserve same-connection data on failure. Late responses cannot repopulate an invalidated draft. |
| Channel refresh | Missing entries are removed by default; keeping them requires explicit selection. Labels/exclusions are pruned with the directory. |
| Default/history selection | Old defaults cannot repopulate dropdowns. Existing task selections remain historical data and require reselection before an unavailable model is sent. Queue/window sends use the same availability guard. |
| Capabilities | Model choices derive from the active channel, with optional engine metadata. Refresh failures do not present stale capability rows. |
| Credential reconnect | A forced reconnect reads the current vault entry, including absence and errors. Cached credentials remain scoped to an unchanged background session. |
| Delayed model save | A newer selection wins; an earlier save cannot replace newer profile state. |
| File inspector | Project/path changes clear prior entries and previews. Switching tabs or closing a preview invalidates pending preview responses. |
| Existing guarded flows | Configuration revisions, task hydration, file loading and per-draft attachments already have scope/revision handling; preserved rather than replaced. |

## Evidence

- TypeScript and production frontend build pass.
- Vitest: 35 files, 122 tests pass.
- Native credential regression: 2 tests pass (rotation/deletion/vault errors and cache isolation/supplied-key priority).
- Full browser regression: 141 cases, 140 passed initially; refresh success-feedback failure was repaired and the same case passed in a targeted four-case rerun. The new delayed model-save regression also passed. No check was skipped or weakened to accept the failure.
- New UI captures verify composer geometry from 960 to 2560 pixels, inspector shown/hidden, light/dark appearance, and visible save controls in short channel dialogs. Browser fixtures exercise UI behavior without real service credentials.
- Installer is built from the final production frontend and native code using the existing Codex engine binaries. Extraction verified all 32 engine/legal resources and matched the packaged executable to the release build. The digest is recorded in VERIFICATION.md and RELEASE-CHECKSUMS.txt.

## Compatibility and limits

No database/configuration schema migration. Existing profiles and local conversations remain readable. This release changes refresh semantics from retaining missing entries to replacing them by default; refreshing may remove manually added entries that the service does not return, and the preview provides an explicit retain option. New model aliases can still be entered after discovery.

Formal signing and previously deferred clean-machine/fault-matrix/long-duration acceptance were not added to this UI work. Visual captures are from the production UI running with test fixtures; native Windows installation and personal workflow acceptance remain with the user.
