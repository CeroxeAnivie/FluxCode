# 性能基线与预算

FluxCode 的性能基线使用本地可重复夹具，不连接生产服务，也不包含用户数据。脚本会先构建测试前端，再启动隔离的 Vite 预览和 Chromium，通过 Playwright 测量首屏、筛选、渠道对话框、历史加载、任务切换、深目录、长文件、对话全文搜索和突发流输出。

运行命令：

```text
pnpm test:performance
```

脚本在 `work/performance-<timestamp>/baseline.json` 写入机器可读结果。报告中的浏览器指标使用 Chromium CDP 的堆回收后 JS 堆和 DOM 计数；耗时从用户动作开始，到目标界面完成两帧绘制为止。它不把网络延迟、真实 Codex 引擎响应或磁盘扫描时间混入前端夹具结果。

## 夹具规模

| 深目录         |                      12 层 |

## 2026-09-25 Windows 基线

环境：Windows、Node v24.13.1、Chromium 153.0.8010.12、生产构建 Vite 预览。每次只运行一个浏览器上下文；结果来自 2026-09-25 重新运行，机器可读结果保存在 `work/performance-*/baseline.json`。

| 指标                   | 虚拟化前 |   当前实现 |   当前预算 |
| ---------------------- | -------: | ---------: | ---------: |
| 首次启动（2,500 任务） |        — | 2,348.9 ms | ≤ 1,500 ms |
| 任务筛选中位数         |        — |   159.7 ms |   ≤ 500 ms |
| 打开渠道页             |        — |   476.4 ms | ≤ 1,000 ms |
| 加载 2,000 条历史      |        — |   304.7 ms | ≤ 1,500 ms |

| 深目录导航（12 层）    |        — |   466.6 ms | ≤ 1,000 ms |

虚拟化后首次启动的 JS 堆为 7.4 MiB，DOM 节点为 12,696，初始只挂载 20 个任务行。加载长历史后 JS 堆为 11.9 MiB、DOM 为 12,580；长文件编辑器状态下 JS 堆为 9.6 MiB、DOM 为 1,233；500 个流增量完成后 JS 堆为 14.6 MiB、DOM 为 12,540。历史消息仍使用已有会话虚拟化，流式事件仍使用 32 ms 批处理和 128 事件上限。

## 已落地的性能措施

- 侧栏任务按可见行虚拟化，任务筛选和项目分组使用记忆化结果，滚动只挂载可视窗口附近的少量行。
- 对话历史使用 `@tanstack/react-virtual`，避免长历史一次性创建消息 DOM。
- 流式增量通过事件批处理合并渲染，保留生命周期事件的即时性。
- 长文件继续使用 CodeMirror 延迟编辑器，打开预览和进入编辑分别测量。

## 解释与限制

这些数字是前端响应基线，不是生产服务 SLA。真实服务还需要单独测量网络、代理、引擎启动、模型首 token、持续输出、磁盘 IO 和真实仓库扫描。内存数据只反映浏览器 JS 堆和 DOM，不等同于整个 FluxCode 进程的私有工作集；持续运行、句柄、CPU 和日志增长需要另一个长时间 native soak。任何依赖真实服务或用户仓库的结论，都必须在声明环境和授权后重新记录。

首次启动 2,348.9 ms 超出当前 1,500 ms 预算，尚未通过启动性能验收。上表记录测量结果，不代表全部预算通过。

## 2026-09-25 收尾优化

目录文件列表复用 TanStack 虚拟化，长文件只读预览复用 CodeMirror；键盘可用方向键/Home/End到达未渲染条目，返回预览恢复原文件位置。新基线使用同一宿主单调时钟跨越页面导航，避免混用页面时间原点。

最新本地代理环境结果：首屏 2,531.9 ms；筛选 25.6 ms；渠道页 442.3 ms；长历史 102.8 ms；任务切换 77.5 ms；12层目录导航 432.1 ms；8,000行文件预览 60.7 ms；编辑器 416.1 ms；全文搜索 118.2 ms；500个流增量 79.8 ms。

首屏 DOM 947、JS 堆4.4 MiB；长历史 DOM827、堆6.4 MiB；长文件 DOM1172、堆8.9 MiB；流结束 DOM1040、堆9.2 MiB。文件列表和长预览的渲染开销明显降低；启动仍高于1,500 ms目标，不放宽预算或伪称通过。原生多进程内存和长时运行不由这些浏览器指标代替。
