# FluxCode 交互准则

让用户持续专注于任务，是产品验收标准，不是最后一轮视觉润色。

## 连续性

- 用户主动选过的内容应立即记忆。已有会话拥有独立模型与推理强度，不受全局默认值影响。
- 新会话沿用最近选择的模型，推理强度默认为“模型默认”（内部值 Off）；切换到已有会话恢复该会话的选择。
- “模型默认”表示省略 Responses 请求的 `reasoning.effort`，采用模型默认值，并不关闭推理；“不推理”显式请求 `none`。模型不支持所选强度时，应清楚呈现服务错误，不能静默降级。
- 失败保留输入和选择；重试无需重新配置。切换项目、任务不应串用草稿和状态。

## 阅读与操作

- 正文、输入框和代码以可读性优先，不能为了容纳更多信息无限缩小文字。
- 字号应可调整并记忆，字体层级随基准字号一致变化。中文、英文和代码均检查。
- 主要操作有充足点击区域；次要信息保持足够对比度；省略内容提供完整提示。
- 键盘可完成模型选择、强度选择、输入、发送和关闭对话框；焦点清晰，关闭后回到发起控件。
- 紧凑窗口优先保留任务正文、输入和发送，工具栏应换行而不是挤掉控件。

## 默认界面保持清爽

- 同一状态在主要位置说明一次，避免工具栏、侧栏和底栏重复显示。
- 不用欢迎页宣传语、装饰性眉题和大卡片挤占工作区。常用起点保留轻量入口。
- 必要的前置条件保持醒目；次要说明靠近相关控件或放入工具提示，不能把每条说明都做成警告横幅。
- 空会话不展示没有数据的上下文面板；创建任务后，相关信息随任务出现。面板只在存在适用内容或用户主动需要时展开。

## 操作区域与前置条件

- 对话框有独立的内容滚动区和底部操作区；内容少时按钮靠底，内容多时不需要滚到底才能保存或取消。
- 提示条右侧集中放置辅助操作、恢复操作和收起按钮。恢复操作只针对它能解决的错误；收起提示不改变后台状态。
- 必须先完成的步骤以图标、明确文字和醒目背景共同提示，并提供直接操作入口；不要只用灰字或颜色传达阻塞原因。
- 能说明原因的错误直接显示，原始技术详情可选中查看；显示和复制前统一脱敏。不要让复制诊断成为理解错误的必经步骤。
- 品牌图标统一来自 assets/icon.svg，包含深色圆角底和蓝色 F；欢迎页、标题栏、消息头像、安装图标和文档保持同一造型。

## 可预期的反馈

- 明确区分连接中、加载历史、发送中、运行中、完成与失败；禁用状态说明原因。
- 运行中的选择锁定，避免显示值与本轮实际值不一致。
- 不抢占用户阅读位置；流式输出只在用户位于底部时跟随。
- 用户打开、关闭的面板和阅读偏好应在合理范围内记忆。

## 验收方法

每次涉及交互的修改都走完整路径：打开项目 → 选择 → 输入 → 发送 → 停止或完成 → 切换任务 → 恢复 → 失败与重试。
同时检查键盘、窄窗口、长模型名、中文、较大字号和重启后的状态。
以上是持续建设标准；验收报告仅声明实际实现和验证的能力，不把规范当作已完成功能清单。
